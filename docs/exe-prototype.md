# EXE原型：第一步

本文保留第一步构建及当时限制；第二步已接入独立后台执行器，当前状态见[EXE版定时获取基金数据](exe-automatic-updates.md)，不将下文旧原型的“未接入”当作最新状态。

2026-10-24。已完成可独立启动的Windows目录式EXE原型，仍使用现有浏览器工作台。本步不是安装程序交付，没有安装向导、桌面快捷方式或卸载入口。

## 本步范围

- EXE包含Python运行时、业务模块与依赖，程序资源随包读取，不要求使用者另装Python。
- 用户数据默认使用 `%LOCALAPPDATA%\QFund`，内部继续分为data/和.local/；程序目录不承担数据写入。源码版仍使用原项目根目录，互不迁移或自动读取对方数据。
- 原型保留运行窗口。双击QFund.exe会尝试打开浏览器，结束时等待任务完成后按Ctrl+C；关闭网页不等于停止服务。
- 原型系统任务入口明确返回尚未接入，不查询、安装或修改Windows任务。源码版自动任务行为保持原状，安装版任务适配留待下一小步。

本机候选产物在 `dist/exe-prototype-step1-2026-10-24-r6/QFund/`，必须保留整个QFund目录及_internal配套文件，不能只复制QFund.exe。历史尝试产物另存保留；这些目录均被忽略，不是GitHub正式版本或安装包。

源码版与原型默认都使用8765端口；同机体验前先在无活动任务时正常停止另一版本，或在命令行给原型指定不同端口。不要为了试用结束正式任务、复制登录资料或覆盖数据。

## 构建入口

使用独立Windows Python 3.12构建环境，先安装requirements.lock.txt，再安装packaging/windows/requirements-build.txt，最后可编辑安装项目。构建工具依赖与运行锁定依赖分开；本轮工具依赖中setuptools80.9.0覆盖的仅是独立构建环境，原源码环境仍保留原版本。

在项目根目录用该构建环境的解释器执行：

```powershell
python scripts/build_exe.py --output-dir dist/新的原型批次目录
```

此处python必须是已准备的构建环境解释器，不能盲用系统旧Python。脚本拒绝覆盖已有输出目录。定义在packaging/windows/qfund.spec；运行依赖不因打包而引入PyInstaller。

本轮从本机原始wheel缓存离线准备PyInstaller6.12.0及对应工具，不声称采用最新版。Plotly7动态模块与validators JSON、Playwright驱动、网页/图标/日历/PS1及项目元数据均纳入构建。

本轮构建基础Python的ssl模块带有读取同目录公开CA文件的定制，初次打包遗漏该资源导致就绪检测失败；spec现按构建解释器实际文件可用性附带该资源，保留原校验语义，不关闭证书校验、不修改系统安全配置。标准CPython无该文件时不额外附加。正式发布宜在通用构建环境重新复核，不能假定所有Python分发都相同。

## 技术检查

原型支持 `--no-browser`、`--port` 和显式绝对路径 `--data-root`。后者用于隔离验证，不迁移数据。

`--diagnose`核对包版本、资源指纹、Edge、Plotly空图生成和Playwright本地驱动握手，不启动浏览器或创建行情。配合`--probe-port`仅读取指定回环端口的health诊断；不访问外站或放宽服务身份校验。技术检查不等于账号登录或真实采集成功。
