# 交易日历与定时维护

当前生产资源仅覆盖2026-01-01至2026-12-31，没有联网同步或下一年度自动下载。未知日期暂停自动采集，手动获取保留原路径。

## 日常设置与排查

在“数据获取”中保存“更新时间”，所有名单基金共用，实际按北京时间UTC+8执行。保存同步已安装任务并保留原停用状态；刷新名单与计划确认时间、任务健康和实际业务结果。新时间只影响生效后的时段，不立即采集。

任务使用安装时Windows用户的普通权限，不保存密码、不主动唤醒。用户需已登录、电脑可执行、源站会话有效。待机可能延迟分派，恢复后按条件检查；不保证精确到秒。系统任务退出0也可能表示未到时、休市或空名单，成功要看运行记录、行情和导出。

排查按“计划时刻→系统分派/电源状态→worker开始→采集运行→保存→导出”核对。可只读查看本项目任务状态、`.local/scheduled-worker.jsonl`及调度/行情记录；Windows事件不可读或缺失时注明未知，不推断没有发生。

## 下一年度或临时休市调整

1. 核对上交所与深交所正式休市公告及临时调整，记录准确来源、核对日期和休市区间。政府调休或商业日历不能替代两所安排，调休上班周末不自动成为交易日。
2. 先完成一致性备份并记录原时间、名单、任务XML及启停状态；确保没有活动采集/导出，再暂停自动触发维护。不改原用户时间或生效点来促成补跑。
3. 当前 `load_calendar()`固定读取 `src/fundlab/scheduling/calendar-2026.json`，只添加另一个年度文件不会生效。集中调整资源及加载入口，保留需要计算补跑的历史覆盖；不能只延长coverage_end而遗漏假期。
4. 核对schema、market、coverage、verified_on、sources、closed_ranges等字段与模块实际校验一致。逐日审计整个覆盖区间，检查节前节后、调休周末、年末年初、时刻边界和合并计划；覆盖外及损坏资源仍应暂停。
5. 运行相关离线检查。若改了加载方式或打包，再核对包中包含实际读取的日历、PS1及其他资源。不把人工测试年份加入生产资源。
6. 空闲时正常停止并重开工作台：日历有进程级缓存，仅刷新网页不会重载。只读核对原时间、名单、日历覆盖和下一时段，恢复原启停状态；只改资源不必重新登记原任务。
7. 失败时保留候选、错误和备份，恢复原资源并重载。若原资源也未覆盖当前日期，继续暂停自动采集；不能删调度账本或改时钟消除错误。
