# QFund 日常维护与问题处理

日常操作见[使用说明](../使用说明.md)，环境准备见[安装说明](installation.md)，技术入口见[开发说明](development.md)。

## 数据与配置位置

| 项目内位置 | 内容 |
|---|---|
| data/fundlab.sqlite3 | 行情、运行与修订记录 |
| data/funds/ | 按代码和安全名称归档的Excel、CSV及metadata |
| data/watchlist.sqlite3 | 自动更新名单 |
| data/schedule.sqlite3 | 计划认领、运行编号、去重、重试预算及结果 |
| data/schedule-settings.json | 共用时间和生效时刻 |
| .local/edge-profile/ | 本人专用浏览器会话，不公开或转发 |
| .local/web-tasks.json | 最近网页任务记录 |
| .local/scheduled-worker.jsonl | 自动执行开始与结果日志 |
| backups/ | 私人备份及校验清单 |

表中目录相对于数据根：源码版为当前项目，安装版为当前用户LOCALAPPDATA/QFund。安装程序位于LOCALAPPDATA/Programs/QFund或用户选择位置；升级和卸载均保留数据，详见[安装版说明](windows-installer.md)。升级同时保留行情、归档、名单、时间和调度记录；不能删除调度库来绕过去重。查询页区间下载不覆盖正式归档。

## 常见问题

- **自动更新未出现**：刷新名单与计划，核对基金启用、时间保存、任务实际状态、日历覆盖和业务结果。任务启用或退出0也可能表示休市、未到时、空名单或当日已经完成。
- **待机后延迟**：任务要求当前用户已登录，程序不主动唤醒。系统分派和电源状态会影响开始时间，不保证精确到秒；关闭网页不会停用自动任务。
- **日历未知**：覆盖外或损坏时暂停自动采集。按[日历维护](trading-calendar-maintenance.md)核对公告后维护，不延长日期来跳过验证。
- **登录失效**：在专用Edge由本人重新登录，按需手动获取；自动失败不会无限弹窗，显式重试也受预算限制。
- **数据保存、导出失败**：关闭占用文件的程序，再“仅重试导出”，不重新采集。
- **强制关窗或断电**：保留记录，核对run_id及数据是否已保存；未完成网页任务重启后标为待确认，不等于数据没保存。
- **端口占用或电脑卡顿**：识别本项目运行窗口和活动任务，正常停止后排查，不泛杀Python、结束用户应用、关闭防火墙或任意修改ACL。

## 备份与恢复

在没有采集、导出、登录或自动批次活动时，可由维护人员执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\backup_verify.py
```

脚本锁住写入，按需短暂停用本项目Windows任务，使用SQLite备份API生成新快照，并在 `.local/restore-drills/` 独立目录做恢复核对，最后恢复原任务状态。不联网、不复制登录profile、不覆盖原库。

以新备份manifest中的 `verified` 和校验结果确认完成，`incomplete`不能当成功备份。若被强制结束或断电，按 `operation-start.json`核对原任务状态，不假定恢复逻辑一定执行。

备份使用显式资料白名单，不保证新加资源自动纳入；维护源码变动后需复查覆盖，当前SVG覆盖限制见开发说明。备份和演练副本仍是私人资料，不要发布。项目同盘备份不代替外部离线备份，恢复演练也不等于新电脑部署已通过。

## 升级和搬迁

安装版等待活动任务结束并正常退出工作台，再运行新版安装包原位置升级；安装器暂停和恢复其严格确认归属的原任务，原停用状态保留。卸载先移除对应任务，保留用户数据。运行中、归属冲突或状态未知时停止，不强制结束应用。不要直接搬动程序目录或用源码维护命令接管安装版任务；跨目录/电脑迁移另行验证。

以下为源码版维护步骤：

原路径升级前先备份，等待任务结束、记录并暂停自动触发、正常停止网页服务。只更新已核对的程序文件，保留data/和.local/，验证后恢复原启停状态，原本停用就仍停用。

变更路径或Python解释器前先处理原Windows任务；其身份绑定项目根目录与解释器，不会自动跟随搬迁。在新路径准备环境、验证数据后再主动安装任务。新电脑由本人重新登录，不复制旧环境或共享浏览器资料。

具体系统分派、长期准时性、所有重启/恢复和登录过期情形并未全面实机验证，不把本地历史样本作为所有电脑可用的保证。
